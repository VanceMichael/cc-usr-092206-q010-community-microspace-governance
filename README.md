# 社区微空间共治

管理社区小微空间从居民诉求、方案协商、改造验收到长期共治运营的完整过程。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构，`fixtures/domain.json` 保存不含真实个人信息的示例。当前参与方包括社区居民（诉求人、议事成员、认领人、志愿者）、街道工作人员（承办人员、复核方）、联建单位与空间运营伙伴（合作商户、值守方）。

资料所依据的领域事实与规则如下：

- 项目生命周期：诉求收集 → 方案协商 → 建设验收 → 运营共治 → 定期复核，居民须先提交诉求并参与方案协商，协商结果是后续运营与复核的对照基准
- 闲置空间被改造为早餐、儿童、文化和运动场景（如屋顶门球场）；开放时段、早餐点值守、收益如何反哺公益等运营规则，比改造前后照片更决定空间能否长久使用
- 项目档案可公开查询：场地产权、安全条件、联建资源、施工验收情况和现行规则
- 运营期在同一项目下持续处理四件事：场地预约、志愿排班、设施报修、公益回馈
- 发生功能调整、临时关闭、噪声纠纷、合作商户退出或认领人变更时，必须保存此前约定的版本，并通知实际受影响者
- 信息边界：个人诉求内容仅向承办人员开放，处理进度向居民公开
- 街道按服务人群、使用情况、维修结果、收益去向四个维度，判断项目是否仍符合最初协商结果

## 本地校验

仓库内的读取模块负责校验示例资料的领域标识、版本、参与方（含角色）、生命周期、事实、运营事项、变更事件与规则、信息边界、复核维度和约束。运行项目自带测试即可检查这些基础资料能够稳定读取。仓库不保存账号、密钥、连接串或真实身份信息。
